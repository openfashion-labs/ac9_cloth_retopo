# チームメンバー向けガイド（社内向け・日本語）

このドキュメントは、openfashion-labs のチームメンバー（特にエンジニアでない方）向けに、
このリポジトリで作業するときのルールをまとめた社内向け手順書です。
外部コントリビューター向けの案内はリポジトリ直下の [CONTRIBUTING.md](../CONTRIBUTING.md) を参照してください。

## 大原則

1. **main ブランチには直接ファイルを置かない**（設定でブロックされています）
2. 変更は必ず **プルリクエスト（PR）** として出し、エンジニアのレビューを受ける
3. **秘密情報は絶対にアップロードしない**（下の「アップロード禁止のもの」参照）

## アップロード禁止のもの

以下が含まれていないか、アップロード前に必ず確認してください。

- パスワード、API キー、トークン（`sk-...` や `ghp_...` のような文字列）
- `.env` という名前のファイル
- 個人情報・顧客データ
- 社内限定の資料
- 社内のファイルパスや内部文書名（`C:\` や社内フォルダのパス、社内メモのファイル名など。
  ファイルの中だけでなく**コミットメッセージや PR の説明文も公開される**ので、そこにも書かない）

パスワードや API キーなどの**認証情報**は、うっかりアップロードしても
自動チェック（gitleaks）が検出して PR をブロックします。
ただし**個人情報や社内資料は自動検出できません**。アップロード前に
自分の目で確認することが唯一の防御線です。
心配なときはアップロード前にエンジニアに聞いてください。

また、3D ファイル（.blend など）の中に埋め込まれたメタデータ（作者名や
スキャン対象者の情報など）も自動検査の対象外です。アップロード前に
ファイルの中身の情報にも注意してください。

※ この一覧は要約です。正式なルールは [CONTRIBUTING.ja.md](../CONTRIBUTING.ja.md) を
参照してください。

## 最初に一度だけ: push 前のローカル検査を有効にする

このリポジトリには、push の直前に個人情報・内部名の混入を検査して止める仕組み
（pre-push フック）が入っています。**一度 push されたものは完全には消せない**ため、
push 前に止めることが唯一確実な防御です。clone したら次の 2 つを実行してください
（AI エージェントに「team-guide の pre-push フックをセットアップして」と頼んでも OK）:

1. リポジトリのフォルダで `git config core.hooksPath .githooks` を実行する
2. 検査パターンのファイルをエンジニアから受け取り、`.git/pii_block_pattern` として
   保存する（このファイルは Git の管理外で、コミットされません。
   **中身をチャットやコミットに貼らないでください**）

パターン未設定でも push はできますが（警告のみ）、検査は CI 任せになります。

## ファイルを追加・変更する手順

使うツールは自由です（AI コーディングエージェント、Git クライアント、GitHub の Web 画面など）。
どのツールを使う場合でも、守ってほしいのは次の 2 点だけです。

1. **main ブランチでは作業しない** — 必ず main から作業用ブランチを切り、
   そこに変更をコミットして PR（プルリクエスト）を出してください
   （main への直プッシュは設定でブロックされています）。
   AI エージェントを使う場合は「main からブランチを切って、変更をコミットして
   PR を出して」と指示すれば OK です
2. PR を出したらエンジニアのレビューを待つ。修正依頼のコメントが付いたら
   対応してください

## ファイルサイズの注意

- **50MB を超えるファイル**は警告が出ます。**100MB を超えるとアップロード自体が失敗**します
- 大きな 3D データを追加したい場合は、先にエンジニアに相談してください

## 困ったら

手順がわからない・エラーが出た・変なものをアップロードしたかも、
というときは自分で対処しようとせず、すぐエンジニアに連絡してください。
早いほど簡単に直せます。
