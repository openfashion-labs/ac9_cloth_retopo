# 01. 考え方と用語

## 何のためのツールか

CLO / Marvelous Designer で作った衣装は、書き出すと三角形の高密度メッシュになります。
そのままでは製品に使えないので、低ポリのリトポメッシュを作り直すことになります。

このアドオンは、その作り直しを **3D のドレープ形状の上ではなく、平面に展開した型紙のかたちの上で** 行うための道具立てです。
型紙の上ならナイフカットも密度調整も素直に効き、縫い合わせの相手側との頂点の対応も 2D の位置で決められます。
3D の形は、平面の頂点を Guide の三角形へバリセントリック（重心座標）で投影して得ます。

## 用語

### Guide

CLO / MD から書き出した高ポリの衣装メッシュ。このアドオンが読む「原本」です。

- Basis シェイプキーが **3D のドレープ形状**
- **Flat SK** で指定したシェイプキーが **UV展開した平面のかたち**

つまり 1 つのオブジェクトが 3D と 2D の両方の座標を持ちます。
Guide は全ての解析が読みますが、解析側から書き込むことはありません（**Bake Island Colors** など、Guide に表示用の色やマテリアルを足す一部の操作は例外です）。

CLO Projector は三角形のみの Guide を要求します（n-gon やクワッドがあると `validate_guide` が弾きます）。
そのため **Create Flat SK** は既定で三角化してから展開します。

### Retopo

これから作る低ポリのリトポメッシュ。サイドバーの全ツールが対象にするオブジェクトです。

**Retopo は常に平面（2D）のまま扱います。** 頂点の追加・削除・移動はすべて平面上で行います。

### Flat SK

UV レイアウトをそのまま頂点座標にしたシェイプキー。名前は `<UV名>_Flattened` で、たとえば `UV_Map_Flattened` になります。
**Create Flat SK** が UV アイランドの境界でメッシュを分割し、各頂点に `(u, v, 0)` を書き込んで作ります（作った直後は値 1.0 で表示されます）。

UV は 0〜1 の範囲なので、この平面は **0〜1 メートルの正方領域**に載ります。単位はメートルです。
Guide の Solidify は **ライブのモディファイアのまま**にしておいてください（適用してしまうと同じメッシュをリトポの Guide として使えなくなります）。

### Mirror

平面の Retopo を Guide の上へ投影した **閲覧専用の 3D 表示**です。

- Retopo と 1:1 のトポロジー（頂点インデックスと面が同じ）を持つ別オブジェクトとして作られます
- **Refresh** を押すたびに毎回ゼロから作り直されます
- 手で編集しても、次の **Refresh** で黙って上書きされます。読み戻されるのは **頂点の選択状態だけ**です（Selection Link オーバーレイ用）

オブジェクト名はコード上 `<Retopo名>_AC93DMirror` で、Retopo とはカスタムプロパティで紐付けられています。
なお UI の説明文では `AC9_3D_Mirror` という呼び方が使われていますが、実際に作られるオブジェクト名は上記の `<Retopo名>_AC93DMirror` です。アウトライナーで探すときはこちらを見てください。

### Final

**Finalize** が作る成果物、`<Retopo名>_Final` という素のメッシュオブジェクトです。

- 形状 = Guide へ投影した 3D 座標
- UV = Retopo 自身の平面レイアウト（だから形と UV が食い違いません）
- シェイプキーなし、`ac9_*` のデータもなし

Retopo 自体は触られません（平面のまま、編集可能なまま）。何度でも実行できます。

### 二面角（dihedral angle）

辺を挟んで隣り合う 2 つの面が、どれだけ折れているかを表す角度です。
**0° が平坦**（2 つの面が同じ平面上にある状態）で、折れが強いほど大きくなります。

**Crease Min Angle** や **Fold Min Angle** のしきい値は、この角度のことです。

## 「2Dが正、3Dは鏡」

以前の方式は、1 つのオブジェクトをシェイプキーの値で 2D（Basis）と 3D（`AC9_3D_Project`）の間で行き来させ、どちらの状態でも編集させるものでした。
3D で編集すると壊れやすい逆投影の経路（新規頂点のスパイク修復を含む）を通ることになり、しかも 2D のレイアウトと 3D の形を同時に見ることができませんでした。

いまの Mirror 方式はここを 2 点で整理しています。

1. **Retopo が唯一の正本で、編集は 2D でだけ行う。** トポロジーと位置の編集は平面上なら簡単で、情報も失われません。
2. **Mirror は (Retopo の 2D + Guide) から決まる純粋な結果物で、毎回作り直される。** ビューアなので、そこへの編集は次の Refresh で消えます。

Refresh の経路は 2 つあります。

- **Object Mode**: 前方投影が Retopo の `AC9_3D_Project` シェイプキーとアタッチメントを書き、Mirror がその座標をコピーします。トポロジーは `retopo.data.polygons` から。
- **Edit Mode（Retopo がアクティブ）**: Retopo の編集用 bmesh から生きた位置とトポロジーを直接読んで投影し、**Mirror だけ**を書きます。Edit Mode では Retopo のメッシュとシェイプキーには一切触りません（そこを触るのが旧 Sync 系オペレータのクラッシュ原因でした）。

## 座標系

- 作業空間は Flat SK 空間、つまり UV を幾何にした 0〜1 の平面。単位はメートル
- 距離系の設定値は多くが mm 指定（Width、Spacing、Scale、Threshold など）
- Guide の Solidify はライブのまま。**Find Folds** はライブの Solidify を見ませんが、その rim は Inset 工程で整えた外周から作られるので問題になりません
- Mirror と Bake Preview Plane はワールド原点近くに置かれます。Preview Plane は平面の Retopo と z ファイトしないよう 5 mm 下（z = -0.005）に置かれます
